# 쉬운 설명 (먼저 읽어주세요)

## 검증이 하는 일 — 한 문장

재무제표 숫자들은 서로 얽혀 있습니다. **세로로 더하면 소계·합계가 맞아야 하고**,
**재무제표 숫자는 주석 어딘가에 근거가 있어야 하고**, **같은 항목이 여러 곳에 나오면
금액이 같아야** 합니다. 사람이 눈으로 대사·검산하던 것을 자동으로 하는 것이 check입니다.
엑셀 검증 셀은 **맞으면 `TRUE`, 틀리면 차이 금액**이 뜹니다.

검증은 크게 세 종류입니다.

- **① 세로합 검산** (C1·C2·C3) — 위아래 숫자를 더해 소계·합계가 맞는지
- **② 계산식 검산** (C7) — 손익계산서처럼 "빼고 더하는" 계산 라인이 맞는지
- **③ 맞대보기(대사)** (C4·C5) — 재무제표 ↔ 주석, 주석 ↔ 주석 금액이 서로 맞는지

## ① 세로합 검산

### C1 — DART가 "합계"라고 표시해둔 칸 (194개)

DSD 파일 안에는 DART 편집기가 **"이 칸은 합계다"**라고 표시(AUTOSUM)해둔 셀이 있습니다.
그런데 **"무엇을 더한 합계인지"는 파일에 저장되지 않습니다.** 그래서 위쪽 숫자들을
더해보고 기재된 합계와 맞는지 확인합니다.

> **예 — 주석6 현금및현금성자산 (당분기말)**
> | 항목 | 금액 |
> |---|---:|
> | 보유현금 | 5,000,000 |
> | 요구불예금 | 12,000,000,000 |
> | 정부보조금 | (100,000,000) |
> | **합계 (DART 표시)** | **11,905,000,000** |
>
> 5,000,000 + 12,000,000,000 − 100,000,000 = **11,905,000,000** → 기재값과 일치 → `TRUE`

**왜 어렵냐면**, 표마다 "어디부터 어디까지 더하는지"가 다릅니다. 예를 들어 표 중간에
소계가 있으면, 최종 합계는 **소계만** 더해야지 소계의 하위 항목까지 또 더하면 이중계산이
됩니다. 그래서 프로그램은 다음 5가지 방식으로 더해보고 **하나라도 맞으면 통과**시킵니다.

1. 소계를 만나면 그 값만 쓰고 소계가 감싼 구간은 건너뛰기
2. 바로 위 연속된 숫자들만
3. 위쪽 첫 합계 칸 직전까지 전부
4. 같은 들여쓰기 수준의 항목들만
5. 위쪽 합계들을 차곡차곡 누적 (예: 부채및자본총계 = 부채총계 + 자본총계)

가로 합계(ROWPART/ROWALL)도 같은 식입니다. 예: 순장부금액 = 총장부금액 + 대손충당금(음수).

### C2 — 들여쓰기로 판단하는 그룹 소계 (12개)

계정과목의 **들여쓰기(빈칸)**를 계층으로 봅니다. 안 들여쓴 항목 아래에 들여쓴 항목들이
이어지면 "위 = 아래들의 합"인지 확인합니다.

> **예 — 재무상태표**
> ```
> Ⅰ.유동자산              15,000,000,000   ← 안 들여씀 = 그룹 머리
>    현금및현금성자산       11,905,000,000   ← 들여씀 = 하위
>    매출채권및기타채권     3,000,000,000
>    기타유동자산              95,000,000
>    …
> ```
> 들여쓴 하위 계정들의 합 = 15,000,000,000 인지 확인 → `TRUE`

⚠️ 이 검증은 **들여쓰기가 유일한 근거**입니다. 회사가 계정과목을 들여쓰지 않으면 작동하지
않습니다. (③번 회사별 대응에서 다룹니다.)

### C3 — 손으로 넣은 합계행 (85개)

C1은 DART가 "합계"라고 표시한 칸만 봅니다. 표시 없이 **손으로 합계를 적은 행**(주석 표의
"소계", "합계" 행 등)도 같은 방식으로 검산합니다.

한 가지 예외 처리: **자본관리 주석**처럼 "부채총계 − 현금 = 조정부채"로 이어지는 표는
"부채총계"가 진짜 데이터라서 합계로 오인하면 안 됩니다. 그래서 **들여쓰기 계층이 실제로
있는 표에서만** 합계행 검산을 합니다.

## ② 계산식 검산 — C7 재무제표 계산 라인 (14개)

손익계산서는 위아래를 무작정 더하는 게 아니라 **빼고 더하는 계산**입니다.

> **예 — 포괄손익계산서 (당분기)**
> ```
> Ⅰ.매출              10,000,000,000
> Ⅱ.매출원가           7,000,000,000
> Ⅲ.매출총이익         3,000,000,000   = 매출 − 매출원가
> Ⅳ.판매비와관리비     2,000,000,000
> Ⅴ.영업이익           1,000,000,000   = 매출총이익 − 판관비
> ```

**부호 규칙**: 계정 이름에 **원가·비용·손실·판매비·법인세**가 들어가면 빼고(−), 나머지는
더합니다(+). 예를 들어 법인세비용차감전순이익 = 영업이익 + 금융수익 − 금융비용 +
기타영업외수익 − 기타영업외비용.

**현금흐름표**는 라벨에 계산식이 직접 써 있습니다 — "Ⅴ.현금및현금성자산의 증가(감소)
**(Ⅰ+Ⅱ+Ⅲ+Ⅳ)**". 이 괄호 안 식을 그대로 읽어서 Ⅰ~Ⅳ 행을 더해 검산합니다.

⚠️ **자본변동표는 아직 검증 안 함** — 기초 + 변동 = 기말 구조에 라벨이 병합되어 있어
별도 처리가 필요합니다 (다음 버전 후보).

## ③ 맞대보기(대사)

### C4 — 재무제표 ↔ 주석 (171개) — v0.4에서 참조번호 비의존으로 재설계

재무제표 금액을 **모든 주석 표에서 전역 검색**합니다. 참조번호는 검색의 전제가 아니라
**역으로 검증되는 대상**입니다 (주석 번호는 매기 바뀌어 실수가 잦으므로).

판정 순서 (재무제표 각 줄의 당기/전기 금액마다):

1. 참조 주석에 금액이 있음 → `TRUE` ("참조 주석 6 확인")
2. 참조 주석 안의 두 값 합·차로 설명됨 → `TRUE` ("조합 일치")
3. **참조 주석엔 없는데 다른 주석에서 발견 → 경고 "참조번호 오류 의심"** ← 핵심 기능
   > 예: 포괄손익계산서의 기타포괄손익-공정가치 평가손익 금액이 —
   > 참조는 주석13인데 실제로는 주석28에만 있음 → 참조번호 확인 필요
4. 참조가 아예 없어도 전역 검색으로 근거 발견 → `TRUE` ("주석 N에서 확인 (참조 표기 없음)")
5. 어디에도 없음 → "미확인" (info — 세후 순액 표시, 부분 참조 등 정상 케이스 존재)

- 우연 일치 방지: 참조 없는 행의 전역 검색은 1,000원 이상 금액만 (주당이익 199원 같은
  소액이 아무 주석에나 걸리는 것 방지)
- ⚠️ 검토 포인트: 우연히 같은 금액이 다른 주석에 있으면 "참조번호 오류 의심"이 오탐이
  될 수 있음 (예: 어떤 부채 금액이 다른 주석의 무관한 항목과 우연히 동액인 경우).
  경고 문구로 안내하되, 오탐 빈도를 보고 임계값·발견 주석 수 조건 조정 예정.

### C5 — 주석 ↔ 주석 (42개)

**같은 계정과목이 여러 주석에 나오면** 금액을 비교합니다.

> **예 — "급여" (당기)**
> 주석24(판매비와관리비) = 1,200,000,000
> 주석33(특수관계자) = 500,000,000  → 다름

⚠️ 여기서 **다른 게 정상인 경우가 대부분**입니다. 판관비 전체의 급여와 특수관계자에게 준
급여는 원래 다른 숫자니까요. 프로그램은 이름만 같은지 볼 뿐 **맥락을 구분하지 못합니다.**
그래서 C5는 경고가 아니라 **"참고"**로만 표시합니다. **현재 가장 노이즈가 많은 검사**이고,
③번(회사별 대응)에서 "실제로 대사해야 하는 쌍만 지정"하는 개선안을 제안합니다.

### C6 — 표기 검사

깨진 숫자, 숫자에 낀 여분 공백, 괄호 짝 안 맞음, 단위 혼용(원/천원/백만원 섞임)을 찾습니다.
**글자 오타는 규칙으로 못 잡습니다.**

## 검증 셀이 TRUE / 차이금액을 정하는 법 (요약)

| 상황 | 검증 셀 표시 |
|---|---|
| 계산·대사가 맞음 | `TRUE` |
| 합계·계산이 안 맞음 | **차이 금액** (기재값 − 계산값), 빨강 |
| 주석에서 근거를 못 찾음 | `미확인`, 빨강 |
| 대사 대상이 아님 | 검증 셀 없음 |

검증 셀은 **엑셀 수식**이라, 엑셀에서 숫자를 고치면 그 자리에서 다시 계산되어 `TRUE` ↔
차이금액이 즉시 바뀝니다.

## 공통 전제

- **숫자 인식**: 전체 일치만 인정 — `1,234,567` / `(1,234)`(음수) / `1,234.56` / `-`(=0).
  콤마 3자리 그룹을 강제해 주석 참조 `6,28,31`을 숫자로 오인하지 않음. `9.56%`는 텍스트.
- **표 구조**: COLGROUP 열 수 + COLSPAN/ROWSPAN을 전개한 그리드 기준. THEAD = 헤더.
- **기간 버킷**: 열 헤더에 `당분기·당기·(당)` → 당기 / `전분기·전기·(전)` → 전기. 그 외 무구분.
- **합계류 라벨**: `합계·소계·총계·계`(공백 무시, 정확 일치) 또는 `…총계`로 끝나는 라벨.
- **섹션 행**: 값 없이 라벨만 있는 행 (`유동자산 :`, `자산`) — 합산 구간의 경계.

## C1. 자동합계(AUTOSUM) 검산 — 194건

DART 편집기가 심어둔 `AUTOSUM` 속성 셀(COLALL/COLPART/ROWALL/ROWPART)을 재계산.
편집기의 실제 합산 범위는 XML에 저장되지 않으므로 **다중 후보** 중 하나라도 일치하면 통과:

| 후보 | 정의 | 커버하는 실제 패턴 |
|---|---|---|
| 스마트 워크 | 위로 올라가며 소계(마크 또는 합계류 라벨)를 만나면 그 값을 더하고, 그 소계가 커버하는 구간(직전 섹션 행까지)은 건너뜀 | 기타자산: 합계 = 유동 소계 + 장기선급비용 |
| 연속 구간 | 섹션 행/소계 전까지의 연속 숫자 | 소계(COLPART) = 섹션 내 항목 합 |
| 직전 자동합계까지 | 위쪽 첫 자동합계 셀 전까지 전부 (섹션 행 투과) | 금융상품 분류표: 금융부채 계 |
| 같은 깊이 | 같은 들여쓰기 깊이의 비합계 행 (섹션 안) | 부채총계 = Ⅰ.유동부채+Ⅱ.비유동부채 |
| 합계류 접두합 | 위쪽 합계류 행들의 누적합 | 부채및자본총계 = 자본총계+부채총계 |

- ROW형(ROWPART/ROWALL): 행 왼쪽으로 연속 숫자(다른 ROW 자동합계에서 멈춤) 또는 왼쪽 전부.
  예: 순장부금액 = 총장부금액 + 대손충당금(음수).
- ✏️ 검토 포인트: "여러 후보 중 하나라도 일치하면 통과"라 우연 일치로 오류를 놓칠 이론적
  가능성 (12자리 금액이라 실제 확률은 극히 낮음). 더 엄격히 갈지?

## C2. 그룹 footing (들여쓰기 계층) — 12건

값 있는 행 뒤에 **더 깊은 들여쓰기** 행들이 이어지면 그룹으로 보고,
그룹 값 = 직계 자식(구간 내 최소 깊이 행들만 — 중첩 그룹 이중합산 방지)의 합.

- 예: `Ⅰ.유동자산`(깊이 0) = `   현금및현금성자산`(깊이 3) 등 하위 계정 합.
- 자식이 2개 미만이면 검사 생략.
- **손익계산서류 제외**: 들여쓰기가 계층이 아님(영업이익 뒤 1칸 들여쓰기는 표현,
  기타포괄손익 소계가 하위 항목과 같은 깊이) → C7이 담당.
- ✏️ 검토 포인트: 들여쓰기(공백 수)가 계층의 유일한 근거 — 회사가 들여쓰기를 안 쓰면 무력.

## C3. 합계행·합계열 footing — 176건

**(a) 합계행(세로)**: 합계류 라벨 행의 각 숫자 열을 C1과 같은 다중 후보로 검산
(AUTOSUM 마크 없는 수기 소계 대상 — **AUTOSUM 미사용 회사의 주력 검사**).

**(b) 합계 헤더 열(가로, v0.4 신설)**: 열 머리글이 `합계/총계/계`인 열은 각 행에서
**형제 열들의 합**이어야 함. 형제 = 그룹 헤더(COLSPAN)를 공유하는 열들(예: 장부금액
그룹의 유동+비유동), 그룹이 없으면 라벨·주석·합계류 외 전체 열(예: 자본변동표의
자본금+기타불입자본+기타자본구성요소+이익잉여금). '(단위: 원)' 전폭 헤더 행은 그룹으로
보지 않음 (실측 캘리브레이션).

- `…총계`형은 **다층 들여쓰기가 실재하는 표에서만** 검사 — 자본관리 표처럼
  `부채총계`가 데이터 라벨인 캐스케이드 표(부채총계−차감=조정부채) 오탐 방지.
- 위쪽에 비합계 숫자 행이 2개 미만이면 생략.

## C7. 재무제표 계산 라인 — 14건

**(a) 손익계산서**: 앵커 라인(라벨이 `…총이익/영업이익/차감전순이익/순이익/총포괄손익`으로
끝남, `주당` 제외) = 직전 앵커 + 사이 행들의 부호합.

- 사이 행은 최소 들여쓰기 깊이만 (기타포괄손익 하위 항목 이중합산 방지)
- **부호 규칙**: 라벨에 `원가·비용·손실·판매비·법인세` 포함 → 뺄셈, 그 외 → 덧셈
- 검증된 관계: 매출총이익=매출−매출원가 / 영업이익=매출총이익−판관비 /
  차감전순이익=영업이익+금융수익−금융비용+기타영업외수익−기타영업외비용 /
  순이익=차감전−법인세비용(수익) / 총포괄손익=순이익+기타포괄손익
- 기타영업외비용이 환입으로 음수여도 괄호 표기가 값에 반영되므로 규칙 성립 (실측 확인)
- ✏️ 검토 포인트: 부호 키워드 목록이 충분한지 (예: `환입`, `충당금전입` 등 특수 계정)

**(b) 라벨 합산식**: 라벨 끝의 `(Ⅰ+Ⅱ+Ⅲ+Ⅳ)`를 파싱해 해당 로마자 행들의 합과 대조
(현금흐름표 Ⅴ·Ⅶ). 모든 표에 적용 (라벨에 식이 있을 때만).

**(c) 자본변동표 (v0.4 신설)**: 라벨에 `기초`가 있는 값 행 → `기말` 행 사이의 변동 행을
열별로 합산해 **기초 + 변동 = 기말** 검증. AUTOSUM·들여쓰기에 의존하지 않는 구조 규칙.

- 섹션(총포괄손익: / 주주와의 거래:)마다 소계 유무가 달라서, 섹션 안에 소계(비들여쓰기
  행)가 있으면 소계만·없으면 항목 전부를 합산 (이중합산 방지 — 실측 캘리브레이션 완료)
- 가로 방향(합계 열 = 자본금+기타불입자본+…)은 C3의 합계 헤더 열 규칙이 담당

## C4. 재무제표 ↔ 주석 대사 — 88건

**매핑 키 = 재무제표의 주석 참조 열** (`주석` 헤더 열의 `6,28,31`).

1. FS 행의 당기/전기 금액(0 제외)에 대해, 참조된 각 주석의 표에서 금액을 수집
   (기간 버킷별 절대값 집합 — 부호는 차감·조정 맥락에 따라 뒤집히므로 절대값 대사)
2. **직접 일치**: 금액이 참조 주석 표에 존재 → 통과
3. **조합 일치**: 주석 내 두 값의 합/차로 설명 → 통과
   (예: 종속기업투자및관계기업투자 = 종속 합계 + 관계 합계)
4. 둘 다 실패 → "미확인" (info) — 세후 표시(확정급여 재측정요소), 부분 참조(특수관계자
   주석은 일부 거래만) 등 정상적 표시 차이가 대부분이라 **경고가 아닌 확인 목록**
- 표가 없는 주석(서술만)은 검사 대상에서 제외.
- 엑셀에는 각 주석 시트 하단 블록 + 살아있는 COUNTIF 수식으로 기록.
- ✏️ 검토 포인트: ① 절대값 대사가 적절한지(부호까지 보려면 오탐 증가) ② 조합을 2개
  값까지만 보는데 3개 이상 조합도 필요한지 ③ "미확인"을 warn으로 올릴 기준

## C5. 주석 ↔ 주석 대사 — 42건

1. 모든 주석 표에서 (정규화 행 라벨, 기간 버킷) → {주석번호: 금액 절대값 집합} 인덱스
2. 같은 (라벨, 기간)이 **2개 이상 주석**에 등장하는데 **공통 금액이 하나도 없으면** 후보 플래그 (info)
3. 제외: 합계류 라벨, 2글자 미만, 일반 라벨(`구분·기타·기초·기말·취득·처분·대체·상각·증가·감소·차감·설정·환입`)

- ✏️ 검토 포인트: ① 실무에서 실제로 대사하는 쌍(예: 차입금 주석 vs 금융상품 주석,

  ② 제외 라벨 추가/삭제 ③ 부분집합 관계(한쪽이 다른 쪽의 구성요소) 허용 여부

# 회사별 DSD 양식 차이 대응 방안 (제안)

**변하지 않는 것 (DART 편집기 표준)** — 현 규칙의 기반이라 회사가 달라도 유지:
ZIP+contents.xml 구조, TABLE/TR/TD 문법, AUTOSUM·ACOPY·AFIXTABLE 속성, 괄호 음수,
콤마 그룹, TITLE/ATOC 구획, THEAD.

**회사마다 변하는 것**: 계정과목명, 주석 번호·제목 체계, 들여쓰기 관행, 기간 라벨
(당기/당분기/당반기/제N기), 단위(원/천원/백만원), 표 구성(연결/별도), 소계 사용 방식.

제안 (우선순위순):

1. **회사 프로파일 = 설정 파일** (`profiles/<회사>.toml`): 키워드성 규칙(기간 버킷,
   합계 라벨, C7 부호 키워드, C5 제외 라벨, 재무제표 시트 분리 키워드)을 코드에서
   데이터로 분리 — 기본 프로파일 + 회사별 오버라이드. 규칙 수정이 코드 수정이 아니게 됨.
2. **캘리브레이션 게이트 절차화**: 새 회사 최초 적용 시 "직전 기수의 심리 완료 DSD"로
   check를 돌려 전수 통과할 때까지 프로파일을 조정하는 온보딩 단계 (초기 캘리브레이션에서 한
   방식의 제도화). 통과 후 그 파일을 회사별 골든 샘플로 등록 → 규칙 변경 시 회귀 검증.
3. **억제 목록(suppression)**: 회사 특성상 항상 뜨는 항목(예: 특수관계자 부분 참조)을
   프로파일에 "확인 완료" 등록 → 매 분기 같은 노이즈 제거. 검증요약에 억제 건수 표시로
   투명성 유지.
4. **C5 화이트리스트 전환 검토**: 라벨 휴리스틱 대신 "실무에서 실제 대사하는 쌍"을
   프로파일에 명시(예: 주석7 매출채권 합계 ↔ 주석28 분류표 매출채권) — 노이즈 대폭 감소,
   회사별 맞춤. 초기 구축 비용은 캘리브레이션 단계에서 1회.
5. **(장기) 계정과목 통제어휘 연동**: 감사 지식 taxonomy(계정과목·주장)와 연결해
   회사별 계정명 차이를 표준 계정으로 정규화 → C4/C5의 라벨 매칭이 회사 독립적이 됨.
